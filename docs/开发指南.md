# DTSoft 动态 WebAPI 插件开发指南

本文说明如何开发并挂载外部 DLL 插件，以及插件通过 `DTSoft.Plugin.Abstractions` 能使用的完整宿主能力。

## 1. 插件机制概览

宿主启动时会扫描插件目录中的外部 DLL，将符合条件的 Controller 注册为 ASP.NET Core MVC ApplicationPart。插件可以提供 WebAPI Controller、插件私有服务注册入口、插件实体模型配置。

插件的主要能力入口是 `IPluginContext`：

```csharp
public interface IPluginContext
{
    IConfiguration Configuration { get; }
    HttpContext? HttpContext { get; }
    HttpRequest? Request { get; }
    ClaimsPrincipal? User { get; }
    string? UserAccount { get; }
    IPluginDbContext DbContext { get; }
    IDtSoftHelper DtSoftHelper { get; }
    T GetRequiredService<T>() where T : notnull;
}
```

插件应该优先通过 `IPluginContext` 使用宿主能力，不要直接依赖宿主内部基础设施。

## 2. 插件目录与启用配置

配置位置：`DTSoftServerApp/appsettings.json`

```json
{
  "DynamicWebApi": {
    "Enabled": true,
    "PluginDirectory": "UserDll"
  }
}
```

说明：

- `Enabled` 为 `false` 时不会加载插件。
- `PluginDirectory` 为空时默认使用 `UserDll`。
- 相对路径基于 `AppContext.BaseDirectory`，也就是服务发布后的程序目录。
- 宿主启动时会自动创建插件目录。
- 当前实现不支持热插拔，放入 DLL 后必须重启宿主。
- 扫描范围只包含插件目录顶层的 `*.dll`，不会递归扫描子目录。
- 宿主默认跳过已经在默认加载上下文中存在同名程序集的 DLL。

## 3. 插件项目建议

插件项目建议使用和宿主一致的目标框架：

```xml
<TargetFramework>net10.0</TargetFramework>
```

建议引用：

```xml
<ItemGroup>
  <Reference Include="DTSoft.Plugin.Abstractions">
    <HintPath>..\path\to\DTSoft.Plugin.Abstractions.dll</HintPath>
    <Private>false</Private>
  </Reference>
</ItemGroup>
```

按需引用：

- `DTSoft.AppService`：需要调用宿主已注册的 AppService 时引用。
- `DTSoft.Models`：需要使用宿主参数、DTO、实体模型时引用。
- `Microsoft.AspNetCore.Mvc.Core` / ASP.NET Core 框架引用：编写 Controller 时需要。
- `Microsoft.EntityFrameworkCore.Relational`：插件实体配置中使用 `ToTable` 等关系型扩展时需要。

插件加载器对白名单外的 `DTSoft.*` 程序集有限制：

- 允许直接引用：`DTSoft.Plugin.Abstractions`、`DTSoft.AppService`、`DTSoft.Models`。
- 禁止直接引用：`DTSoft.Core`、`DTSoftServerApp` 等其他 `DTSoft.*` 程序集。
- `Microsoft.*`、`System.*`、`netstandard`、`Serilog`、`Scalar` 等共享依赖优先使用宿主默认加载上下文。
- 第三方私有依赖可以随插件发布输出一起放到插件目录，并保留 `.deps.json`，由插件自己的加载上下文解析。

## 4. 插件 DLL 被识别的条件

一个 DLL 至少包含下面任意一种类型，才会被宿主作为有效插件记录：

- 公开、非抽象、继承 `ControllerBase` 的 Controller。
- 公开、非抽象、实现 `IDynamicWebApiPlugin` 的插件模块。
- 公开、非抽象、实现 `IPluginEntityModelConfiguration` 的实体模型配置。

Controller 判断条件来自源码：

```csharp
type is { IsAbstract: false, IsClass: true, IsPublic: true }
&& typeof(ControllerBase).IsAssignableFrom(type)
```

因此 Controller 必须是 `public class`，不能是内部类或抽象类。

## 5. 插件元数据

插件可以使用 `DynamicWebApiPluginAttribute` 声明名称、描述、版本：

```csharp
using DTSoft.Plugin.Abstractions;

[assembly: DynamicWebApiPlugin("订单扩展", Description = "订单插件接口", Version = "1.0.0")]
```

也可以标注在公开类型上：

```csharp
[DynamicWebApiPlugin("订单扩展", Description = "订单插件接口", Version = "1.0.0")]
public sealed class OrderPluginModule : IDynamicWebApiPlugin
{
    public void ConfigureServices(IServiceCollection services, IConfiguration configuration)
    {
    }
}
```

加载日志中的插件名称优先级：

1. 程序集上的 `DynamicWebApiPluginAttribute.Name`
2. 类型上的 `DynamicWebApiPluginAttribute.Name`
3. 程序集名称

## 6. Controller 开发示例

```csharp
using DTSoft.Plugin.Abstractions;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;

namespace UserPlugin;

[ApiController]
[Authorize]
[Route("api/plugin/user/[controller]/[action]")]
public sealed class DemoController(IPluginContext pluginContext) : ControllerBase
{
    [HttpGet]
    public IActionResult Me()
    {
        var account = pluginContext.UserAccount;
        if (string.IsNullOrWhiteSpace(account))
        {
            return Unauthorized(new { success = false, Msg = "未登录" });
        }

        var isAdmin = pluginContext.DtSoftHelper.IsAdmin(account);
        return Ok(new
        {
            success = true,
            data = new
            {
                account,
                isAdmin,
                path = pluginContext.Request?.Path.Value
            }
        });
    }
}
```

访问示例：

```text
GET /api/plugin/user/Demo/Me
Authorization: Bearer <token>
```

注意：

- 插件路由由 Controller 自己声明，宿主不会自动增加统一前缀。
- 需要登录保护时使用 `[Authorize]`。
- 公开接口可使用 `[AllowAnonymous]`，但要自行控制风险。
- 宿主 JSON 配置保持 PascalCase，不使用默认 camelCase。

## 7. `IPluginContext` 能力说明

### 7.1 `Configuration`

类型：`Microsoft.Extensions.Configuration.IConfiguration`

用途：

- 读取宿主配置。
- 读取插件自己的配置节点。

示例：

```csharp
var enabled = pluginContext.Configuration.GetValue<bool>("MyPlugin:Enabled");
var endpoint = pluginContext.Configuration["MyPlugin:Endpoint"];
```

### 7.2 `HttpContext`

类型：`Microsoft.AspNetCore.Http.HttpContext?`

用途：

- 获取当前请求上下文。
- 读取 TraceIdentifier、连接信息、响应对象、服务容器等。

注意：

- 只在 HTTP 请求链路中有值。
- 后台任务或非请求场景可能为 `null`。

### 7.3 `Request`

类型：`Microsoft.AspNetCore.Http.HttpRequest?`

用途：

- 获取请求路径、查询参数、Header、Body 等。

示例：

```csharp
var path = pluginContext.Request?.Path.Value;
var keyword = pluginContext.Request?.Query["keyword"].ToString();
```

### 7.4 `User`

类型：`System.Security.Claims.ClaimsPrincipal?`

用途：

- 读取当前认证用户的 Claims。
- 执行自定义权限判断。

示例：

```csharp
var claims = pluginContext.User?.Claims.Select(x => new { x.Type, x.Value });
```

### 7.5 `UserAccount`

类型：`string?`

宿主会按下面顺序从 Claims 中解析账号：

1. `ClaimTypes.NameIdentifier`
2. `sub`
3. `ClaimTypes.Name`
4. `name`
5. `unique_name`

如果没有当前用户或 Claims 中没有这些字段，返回 `null`。

示例：

```csharp
var account = pluginContext.UserAccount;
if (string.IsNullOrWhiteSpace(account))
{
    return Unauthorized(new { success = false, Msg = "未登录" });
}
```

### 7.6 `DbContext`

类型：`IPluginDbContext`

插件可访问的数据库上下文能力，详见第 9 节。

### 7.7 `DtSoftHelper`

类型：`IDtSoftHelper`

宿主开放给插件的系统辅助能力，详见第 8 节。

### 7.8 `GetRequiredService<T>()`

用途：

- 从宿主 DI 容器获取已注册服务。
- 获取插件自己在 `IDynamicWebApiPlugin.ConfigureServices` 中注册的服务。
- 获取日志、宿主 AppService 等。

示例：

```csharp
var logger = pluginContext.GetRequiredService<ILogger<DemoController>>();
var userApp = pluginContext.GetRequiredService<UserApp>();
```

注意：

- 服务未注册会抛出异常。
- 插件若要获取 `DTSoft.AppService` 中的类型，需要插件项目引用 `DTSoft.AppService`。
- 不建议通过该方法绕过抽象层强依赖宿主内部类型。

### 7.9 运行日志 `ILogger<T>`

外部 DLL 可以使用 ASP.NET Core 标准日志接口 `ILogger<T>` 写入运行日志。插件日志会进入宿主日志管道，当前宿主已在 `Program.cs` 中接入 Serilog，因此插件运行日志会跟随宿主 Serilog 配置输出到控制台、文件或其他已配置目标。

构造函数注入示例：

```csharp
using DTSoft.Plugin.Abstractions;
using Microsoft.AspNetCore.Mvc;
using Microsoft.Extensions.Logging;

public sealed class DemoController(
    IPluginContext pluginContext,
    ILogger<DemoController> logger) : ControllerBase
{
    [HttpGet]
    public IActionResult Test()
    {
        logger.LogInformation(
            "插件接口被调用，UserAccount={UserAccount}, Path={Path}",
            pluginContext.UserAccount,
            pluginContext.Request?.Path.Value);

        return Ok(new { success = true });
    }
}
```

通过 `IPluginContext` 获取示例：

```csharp
var logger = pluginContext.GetRequiredService<ILogger<DemoController>>();
logger.LogWarning("插件业务警告：Code={Code}, UserAccount={UserAccount}", code, pluginContext.UserAccount);
```

建议：

- 使用结构化日志参数，不要用字符串拼接。
- 不要记录密码、Token、密钥、完整连接字符串等敏感信息。
- 异常日志使用 `logger.LogError(ex, "插件处理失败，OrderId={OrderId}", orderId)`，保留异常堆栈。
- `ILogger<T>` 写的是运行日志，不等同于系统业务操作日志表。

## 8. `IDtSoftHelper` 内置方法

`IDtSoftHelper` 是当前宿主显式开放的系统能力入口：

```csharp
public interface IDtSoftHelper
{
    bool IsAdmin(string userAcc);
    string? GetRoleName(long roleId);
    bool IsContainRole(long roleId, string userAcc);
    string GetLoginUserAccountFromJwt(string token);
    Task<JsonObject> CheckAccStatus(string userAcc);
    Task<JsonArray> GetDictionaryItemsAsync(string dictCode);
}
```

### 8.1 `IsAdmin(string userAcc)`

判断用户是否具有管理员权限。

源码行为：

- 空账号返回 `false`。
- 查询用户所属角色。
- 只要所属角色中存在角色名为 `Administrator` 的角色，即返回 `true`。
- 结果缓存 30 秒，缓存键基于账号小写。

示例：

```csharp
var isAdmin = pluginContext.DtSoftHelper.IsAdmin(account);
```

### 8.2 `GetRoleName(long roleId)`

根据角色 ID 获取角色名称。

源码行为：

- 查询 `SysRole.ItemId == roleId` 的 `RoleName`。
- 未找到时返回空字符串。
- 结果缓存 10 分钟。

示例：

```csharp
var roleName = pluginContext.DtSoftHelper.GetRoleName(roleId);
```

### 8.3 `IsContainRole(long roleId, string userAcc)`

判断账号是否属于指定角色。

源码行为：

- 空账号返回 `false`。
- 查询 `SysRoleMember` 中是否存在 `UserAcc == userAcc && RoleId == roleId`。
- 结果缓存 30 秒。

示例：

```csharp
var inRole = pluginContext.DtSoftHelper.IsContainRole(roleId, account);
```

### 8.4 `GetLoginUserAccountFromJwt(string token)`

从 JWT 字符串中解析登录账号。

源码行为：

- 使用 `JwtSecurityTokenHandler.ReadJwtToken` 读取 token。
- 依次匹配 `ClaimTypes.NameIdentifier`、`JwtRegisteredClaimNames.NameId`、`JwtRegisteredClaimNames.Sub`、`JwtRegisteredClaimNames.UniqueName`、`ClaimTypes.Name`、`name`。
- 解析失败或找不到账号时返回空字符串。
- 该方法只读取 JWT，不验证签名和有效期。鉴权仍应依赖 ASP.NET Core `[Authorize]`。

示例：

```csharp
var token = pluginContext.Request?.Headers.Authorization.ToString().Replace("Bearer ", "");
var account = string.IsNullOrWhiteSpace(token)
    ? ""
    : pluginContext.DtSoftHelper.GetLoginUserAccountFromJwt(token);
```

### 8.5 `CheckAccStatus(string userAcc)`

检查账号状态。

源码行为：

- 空账号返回 `{ StateCode: 0, success: false, Msg: "账号不能为空" }`。
- 账号禁用时返回 `{ StateCode: 0, success: false, Msg: "请求失败，账号已被禁用！" }`。
- 正常时返回 `{ StateCode: 0, success: true, Msg: "" }`。

示例：

```csharp
var status = await pluginContext.DtSoftHelper.CheckAccStatus(account);
if (status["success"]?.GetValue<bool>() != true)
{
    return BadRequest(status);
}
```

### 8.6 `GetDictionaryItemsAsync(string dictCode)`

根据字典编码获取启用的字典项。

源码行为：

- 空编码返回空 `JsonArray`。
- 查询 `SysDictionaryData` 中 `DictCode` 匹配且 `Enabled == true` 的数据。
- 按 `Sort`、`ItemLabel` 排序。
- 返回字段：`Label`、`Value`、`TagType`。

示例：

```csharp
var items = await pluginContext.DtSoftHelper.GetDictionaryItemsAsync("OrderStatus");
return Ok(new { success = true, data = items });
```

## 9. `IPluginDbContext` 数据库能力

接口：

```csharp
public interface IPluginDbContext
{
    DatabaseFacade Database { get; }
    DbSet<TEntity> Set<TEntity>() where TEntity : class;
    DbConnection GetDbConnection();
    Task<int> SaveChangesAsync(CancellationToken cancellationToken = default);
}
```

当前实现由 `SysDbContext` 提供，和宿主业务共用同一个请求作用域数据库上下文。

### 9.1 `Set<TEntity>()`

获取 EF Core `DbSet<TEntity>`。

用途：

- 查询插件自定义实体。
- 查询宿主模型实体，但插件项目需要引用 `DTSoft.Models`。

示例：

```csharp
var list = await pluginContext.DbContext
    .Set<PluginOrder>()
    .AsNoTracking()
    .Where(x => x.CreatedBy == account)
    .ToListAsync();
```

### 9.2 `SaveChangesAsync(...)`

提交当前作用域内的 EF Core 变更。

示例：

```csharp
pluginContext.DbContext.Set<PluginOrder>().Add(order);
await pluginContext.DbContext.SaveChangesAsync();
```

### 9.3 `Database`

获取 EF Core `DatabaseFacade`。

用途：

- 开启事务。
- 执行迁移相关能力。
- 访问数据库 Provider 信息。
- 执行 `ExecuteSqlRawAsync` 等 EF Core 扩展。

示例：

```csharp
await using var tx = await pluginContext.DbContext.Database.BeginTransactionAsync();
// ...
await pluginContext.DbContext.SaveChangesAsync();
await tx.CommitAsync();
```

### 9.4 `GetDbConnection()`

获取底层 `DbConnection`。

用途：

- 执行 ADO.NET 命令。
- 和 Dapper 等轻量 ORM 配合使用。

示例：

```csharp
var connection = pluginContext.DbContext.GetDbConnection();
var shouldClose = connection.State != ConnectionState.Open;
if (shouldClose)
{
    await connection.OpenAsync();
}

try
{
    await using var command = connection.CreateCommand();
    command.CommandText = "select 1";
    var value = await command.ExecuteScalarAsync();
}
finally
{
    if (shouldClose && connection.State == ConnectionState.Open)
    {
        await connection.CloseAsync();
    }
}
```

注意：

- 使用宿主连接时不要随意 Dispose 连接对象。
- 打开连接后应按进入前状态决定是否关闭。
- 插件 SQL 需要兼容当前宿主数据库类型：`MySql`、`SqlServer`、`Oracle`、`PostgreSql`。

## 10. 插件自定义实体

插件自定义实体需要实现模型配置，否则 EF Core 不认识该实体。

实体示例：

```csharp
namespace UserPlugin.Entities;

public sealed class PluginOrder
{
    public long Id { get; set; }
    public string OrderNo { get; set; } = "";
    public string CreatedBy { get; set; } = "";
    public DateTime CreatedTime { get; set; }
}
```

模型配置示例：

```csharp
using DTSoft.Plugin.Abstractions;
using Microsoft.EntityFrameworkCore;
using UserPlugin.Entities;

namespace UserPlugin;

public sealed class PluginOrderModelConfiguration : IPluginEntityModelConfiguration
{
    public void Configure(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<PluginOrder>(entity =>
        {
            entity.ToTable("plugin_order");
            entity.HasKey(x => x.Id);
            entity.Property(x => x.OrderNo).HasMaxLength(50);
            entity.Property(x => x.CreatedBy).HasMaxLength(50);
        });
    }
}
```

宿主加载行为：

- 插件中所有公开、非抽象、实现 `IPluginEntityModelConfiguration` 的类型都会注册为单例。
- `SysDbContext.OnModelCreating` 中会逐个调用 `Configure(modelBuilder)`。
- 实体注册只负责 EF Core 模型识别，不会自动创建或升级数据库表。
- 插件表结构需要通过运维 SQL、插件初始化逻辑或其他发布流程提前准备。

PostgreSQL 注意事项：

- 宿主会在 `OnModelCreating` 末尾遍历所有实体。
- `DateTime` / `DateTime?` 会统一配置为 `timestamp without time zone`。
- UTC 时间会转换为本地时间后去掉 `Kind`。

## 11. 插件私有服务注册

插件可以实现 `IDynamicWebApiPlugin` 注册自己的服务：

```csharp
using DTSoft.Plugin.Abstractions;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace UserPlugin;

public sealed class UserPluginModule : IDynamicWebApiPlugin
{
    public void ConfigureServices(IServiceCollection services, IConfiguration configuration)
    {
        services.AddScoped<UserPluginService>();
    }
}
```

使用示例：

```csharp
public sealed class DemoController(
    IPluginContext pluginContext,
    UserPluginService pluginService) : ControllerBase
{
}
```

或者：

```csharp
var pluginService = pluginContext.GetRequiredService<UserPluginService>();
```

加载行为：

- 宿主用无参构造函数创建 `IDynamicWebApiPlugin` 实现。
- `ConfigureServices` 在 `builder.Build()` 前执行。
- 插件模块构造函数不要依赖 DI 注入。
- 多个模块都会执行，单个模块注册失败会记录失败信息，但不影响继续扫描其他类型。

## 12. 可通过 DI 使用的宿主内置服务

插件可以通过 `pluginContext.GetRequiredService<T>()` 获取宿主已经注册的服务。当前源码中面向业务最常用的是 `DTSoft.AppService` 下的 Scoped 服务。

使用前提：

- 插件项目引用 `DTSoft.AppService`。
- 方法参数类型通常来自 `DTSoft.Models`，因此多数场景也要引用 `DTSoft.Models`。
- 这些服务原本服务于宿主 Controller，返回结构以 `JsonObject`、DTO、元组或实体为主。

using DTSoft.AppService.User;
using DTSoft.Plugin.Abstractions;
using Microsoft.AspNetCore.Authorization;

namespace UserPlugin;

[Authorize]

## 14. 插件完整示例

```csharp
using DTSoft.Plugin.Abstractions;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Logging;

[assembly: DynamicWebApiPlugin("订单插件", Description = "订单扩展接口", Version = "1.0.0")]

namespace OrderPlugin;

public sealed class OrderPluginModule : IDynamicWebApiPlugin
{
    public void ConfigureServices(IServiceCollection services, IConfiguration configuration)
    {
        services.AddScoped<OrderNumberService>();
    }
}

public sealed class OrderNumberService
{
    public string NewOrderNo() => $"PO{DateTime.Now:yyyyMMddHHmmssfff}";
}

public sealed class PluginOrder
{
    public long Id { get; set; }
    public string OrderNo { get; set; } = "";
    public string CreatedBy { get; set; } = "";
    public DateTime CreatedTime { get; set; }
}

public sealed class PluginOrderModelConfiguration : IPluginEntityModelConfiguration
{
    public void Configure(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<PluginOrder>(entity =>
        {
            entity.ToTable("plugin_order");
            entity.HasKey(x => x.Id);
            entity.Property(x => x.OrderNo).HasMaxLength(50);
            entity.Property(x => x.CreatedBy).HasMaxLength(50);
        });
    }
}

[ApiController]
[Authorize]
[Route("api/plugin/order/[controller]/[action]")]
public sealed class OrdersController(
    IPluginContext pluginContext,
    OrderNumberService orderNumberService,
    ILogger<OrdersController> logger) : ControllerBase
{
    [HttpPost]
    public async Task<IActionResult> Create()
    {
        var account = pluginContext.UserAccount;
        if (string.IsNullOrWhiteSpace(account))
        {
            return Unauthorized(new { success = false, Msg = "未登录" });
        }

        var order = new PluginOrder
        {
            Id = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds(),
            OrderNo = orderNumberService.NewOrderNo(),
            CreatedBy = account,
            CreatedTime = DateTime.Now
        };

        pluginContext.DbContext.Set<PluginOrder>().Add(order);
        await pluginContext.DbContext.SaveChangesAsync();

        logger.LogInformation(
            "插件订单创建成功，OrderNo={OrderNo}, UserAccount={UserAccount}",
            order.OrderNo,
            account);

        return Ok(new { success = true, data = order });
    }

    [HttpGet]
    public async Task<IActionResult> List()
    {
        var account = pluginContext.UserAccount ?? "";
        var list = await pluginContext.DbContext
            .Set<PluginOrder>()
            .AsNoTracking()
            .Where(x => x.CreatedBy == account)
            .OrderByDescending(x => x.CreatedTime)
            .ToListAsync();

        return Ok(new { success = true, data = list });
    }
}
```

    OrderNo varchar(50) not null,

    CreatedTime datetime not null

## 15. 发布步骤

1. 编译插件项目。
2. 将插件主 DLL 放入宿主发布目录下的 `UserDll`，或配置的插件目录。
3. 如插件有第三方私有依赖，将依赖 DLL 和 `.deps.json` 一起放入插件目录。
4. 不要把 `DTSoft.Plugin.Abstractions.dll`、`DTSoft.AppService.dll`、`DTSoft.Models.dll` 的插件私有副本作为独立依赖强行加载，宿主要求这些程序集由宿主默认上下文提供。
5. 准备插件需要的数据库表结构。
6. 重启宿主服务。
7. 查看启动日志中的 `[PLUGINS]` 段确认加载结果。

启动日志成功示例：

```text
[PLUGINS]
  Loaded : 1
  - 订单插件 | Assembly: OrderPlugin | Controllers: 1 | Modules: 1
```

加载失败时宿主会记录：

```text
[PLUGINS] Load failed: <FilePath> | <Message> | <ExceptionType>
```

## 16. 常见问题

### 16.1 插件 DLL 放进目录后没有接口

检查：

- `DynamicWebApi:Enabled` 是否为 `true`。
- DLL 是否放在发布目录的 `UserDll`，而不是源码目录的 `UserDll`。
- Controller 是否是 `public`、非抽象，并继承 `ControllerBase`。
- Controller 是否声明了 `[Route]`。
- 宿主是否已经重启。
- 启动日志是否有 `[PLUGINS] Load failed`。

### 16.2 报错“插件只能直接引用 ...”

原因是插件直接引用了非白名单的 `DTSoft.*` 程序集，例如 `DTSoft.Core`。

处理：

- 移除对 `DTSoft.Core`、`DTSoftServerApp` 的引用。
- 改用 `IPluginContext`、`IDtSoftHelper`、`IPluginDbContext`。
- 需要业务能力时引用并调用 `DTSoft.AppService`。

### 16.3 `GetRequiredService<T>()` 报服务未注册

检查：

- `T` 是否是宿主已注册的服务。
- 插件私有服务是否已在 `IDynamicWebApiPlugin.ConfigureServices` 中注册。
- 插件模块是否是 `public`、非抽象、有无参构造函数。
- 插件模块注册时是否抛异常。

### 16.4 `Set<TEntity>()` 报实体未包含在模型中

检查：

- 是否实现了 `IPluginEntityModelConfiguration`。
- 配置类是否 `public`、非抽象。
- 插件是否被宿主成功加载。
- `Configure(ModelBuilder modelBuilder)` 中是否调用了 `modelBuilder.Entity<TEntity>()`。

### 16.5 表不存在或字段不存在

插件实体配置不会自动创建表。需要提前执行数据库脚本，或在插件初始化逻辑中显式创建表。

### 16.6 `UserAccount` 为空

检查：

- Controller 是否使用 `[Authorize]`。
- 请求是否携带有效 Bearer Token。
- JWT Claims 是否包含 `NameIdentifier`、`sub`、`Name`、`name`、`unique_name` 中至少一个。

### 16.7 第三方依赖加载失败

检查：

- 插件发布输出中的依赖 DLL 是否一起放入插件目录。
- `.deps.json` 是否保留。
- 依赖版本是否和宿主共享依赖冲突。

## 17. 开发约定建议

- 插件接口路由建议统一使用 `api/plugin/<业务域>/[controller]/[action]`。
- 插件表名建议加业务前缀，例如 `plugin_order`，避免和宿主表冲突。
- 需要当前用户时优先使用 `pluginContext.UserAccount`。
- 权限判断优先使用 `[Authorize]`，业务内再用 `DtSoftHelper` 做管理员或角色判断。
- 查询默认使用 `AsNoTracking()`。
- 写入操作明确调用 `SaveChangesAsync()`。
- 不要在插件中保存宿主 `DbConnection`、`HttpContext`、`IPluginContext` 的静态引用。
- 不要在插件模块构造函数中做数据库访问或读取请求上下文。
- 对外返回结构建议和宿主保持一致：`{ success = true/false, data = ..., Msg/message = ... }`。
